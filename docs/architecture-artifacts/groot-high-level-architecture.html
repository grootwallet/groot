IPC may carry

Addresses, balances, UTXOs, public descriptors/xpub metadata, proposal reviews, statuses, bounded PSBT exchange.

IPC must never carry

Mnemonic, seed, xpriv/private descriptor, credential after command use, decrypted signing material.

Network egress

Core JSON-RPC; verified compact-filter traffic; no REST app server, hosted database, or silent backend fallback.

External media

Public descriptor backups and PSBTs via native files / bounded UR; privacy-sensitive but non-spending by themselves.

Security invariants

1

Secrets stay native. Mnemonic, seed, private descriptors and signing material never enter the webview.

2

Review the real transaction. Rust derives review fields from the persisted unsigned PSBT; the UI does not recompute truth.

3

Fail closed. Wrong credential, foreign/mutated PSBT, unknown signer, route mismatch, gap risk, or chain mismatch stops the operation.

4

Persist coherently. Revealed address + permanent label, proposal + BDK change, and broadcast + intent + notice commit atomically.

5

Integer accounting. Satoshis are safe integers; fee rates are positive sat/vB.

Technology stack

  • Shell: Tauri 2.11.5, desktop/mobile shared Rust entry point
  • UI: SvelteKit 2.69.3, Svelte 5.56.5, static SPA
  • Wallet: Rust, BDK Wallet 3.1.0, Bitcoin/Miniscript, BIP39
  • Storage: SQLite via BDK/rusqlite, device-bound AES-GCM envelopes
  • Node: Bitcoin Core RPC; direct HTTPS or explicit onion-over-loopback-SOCKS5
  • Discovery: Core or bdk_kyoto 0.17.0 compact filters
  • Signing: Bitcoin Core HWI subprocess; file and UR PSBT interchange
  • Release: locked dependencies, SBOM, supply-chain checks, reproducibility/signature gates

Mainnet & release gates

Mainnet compile-time disabled

No selectable runtime mainnet. Trusted Rust gate is false before wallet database open.

Approval evidence required

ADR 0012 supersession, threat model, exact-device physical matrix, public-network rehearsal, recovery checklist, reproducible signed package, independent approval.

Platform boundaries remain explicit

Non-Apple public-network secure storage fails closed; terminated background delivery is out of scope; mobile native recovery certification is pending.

Compact-filter limits

Memory-only shared headers/filters in pinned engine; recovery, durable cache and direct P2P broadcast are not claimed.

Backup & recovery paths

Software wallet · secret path

Native 24-word sheet → exact-order challenge or deferred marker → device-bound encrypted mnemonic. Clean recovery uses native word entry + original BIP39 passphrase + bounded full scan.

Hardware wallet · signer-owned secret

Groot stores only public BIP84 identity and local app-PIN verifier. Recovery depends on the signer's own backup plus Groot's public descriptor export.

Multisig · public coordinator backup

BSMS / descriptor / Groot JSON exports are watch-only and privacy-sensitive. Recovery validates network, branches, descriptor identity and first address before creating state.

Important unresolved boundaries

  • Mobile native mnemonic entry/presentation and non-exportable secure storage are not certified across iOS/Android.
  • HWI inherits vendor firmware, USB stack, host process and physical display assumptions; exact-model evidence cannot be generalized.
  • Compact-filter peers can affect availability and privacy; current engine redownloads public filters after restart.
  • Remote Core confidentiality/availability rests on user endpoint, TLS/Tor configuration and exact-chain verification.
  • Signed update/package/notarization/reproducibility evidence is incomplete; a green test suite is not release proof.
  • Single-key proposals persist after restart, but the generic UI lacks a proposal selector.
