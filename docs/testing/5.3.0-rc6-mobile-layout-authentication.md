# RC6 mobile layout and credential flow

The owner completed RC5 physical pairing and reported crowded copy, notices touching cards, content scrolling behind the status bar and fixed actions, a stopped black camera preview before final PIN entry, misleading phone connection labels and repeated iOS passcode prompts.

RC6 gives native mobile a scroll region between its fixed safe header and bottom controls, separates notices, shortens the pairing/overview/policy text and labels phone connections as QR. A verified QR destroys the scanner and replaces its preview/progress with a compact result before credential entry; a rejected PIN retains that verified result for retry.

ADR 0097 replaces repeated iOS user-presence prompts with Groot credential authorization, retaining device binding, passcode-required device-only Keychain storage, encrypted-file formats and old Keychain items. Legacy access can require one final owner approval. Only successful Groot credential decryption permits adding the same wrapping key to the new policy account. Wrong credentials, cancelled approval and copy failures do not grant access. No seeds, wallet files, profiles or hardware signers are reset. Release-source pins remain untouched.

Coverage includes native credential/copy failure ordering, original envelope/context tests, full Rust lint/tests, desktop/mobile light/dark QR completion and PIN retry, phone connection details, native header/action geometry and existing pairing/signing/setup regressions. Browser captures use synthetic data. Physical legacy/new key authorization, background/restart and native layout verification are recorded separately with exact candidate artifacts; no secret entry may be captured.

The local Testnet4 node was stopped while Mainnet was running. It was started separately using its existing data directory, local-only RPC 48332 and P2P 48333; it connected to peers and began downloading blocks. [Mac instructions](testnet4-local-mac.md) distinguish desktop loopback from a phone's trusted remote node route.

Mandatory `pnpm validate` still reaches the unchanged reviewed-source snapshot failure. Internal rehearsal evidence is not public release approval or hardware certification.
