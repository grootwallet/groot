# Testnet4 iPhone development handoff

Owner request, 2026-10-18; refs #6 and #116. [ADR 0091](../adr/0091-testnet4-ios-development.md) selects Testnet4 for this local development build. This supersedes the earlier Signet development choice, not ADR 0089's safety restrictions. Native/web consistency and release source-policy gates remain enabled; no reviewed pins or trust material changed.

## Identity and isolation

The app is **Groot Testnet4 Dev**, `app.groot.wallet.mobile.testnet4.dev`, iOS 17 minimum, baseline version 5.2.0 with development source identity. It has separate storage from desktop and earlier mobile installs. No profile was copied, migrated, deleted or reinterpreted; no wallet format or BIP support changed. Testnet4 reuses existing BIP94/network handling. The separate mobile signer branch remains unmerged.

Both frontend and Rust must compile for Testnet4, with bundled native assets and no LAN development frontend. This is not a 5.3 release candidate, Android build, authenticated pairing/watch implementation, phone-held signer or broadcast capability. Native mobile restrictions remain unchanged.

## Mismatch found on device

The first installed Testnet4-labeled development app correctly stopped at the native/web consistency gate: its web UI was Testnet4 but its Rust library had compiled as Regtest. Compilation, code signing, a shell environment setting and an unrelated all-feature Clippy pass did not establish the linked app's actual network. The pre-install verification missed that boundary; that initial binary is diagnostic-only.

The pinned Tauri CLI 2.11.4 mobile bridge forwards selected environment prefixes, including `CARGO_*` and `PATH`, but not Groot's custom `GROOT_*` setting. Its Xcode build therefore reached the existing Rust Regtest default. This behavior is visible in the [upstream CLI environment handoff](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.11.4/crates/tauri-cli/src/mobile/mod.rs#L284-L305) and was confirmed by the linked library's Cargo dependency/build-script output.

The scoped iOS Cargo runner supplies the fixed network through Cargo's local `env.GROOT_BUILD_NETWORK` configuration. The launcher explicitly captures the underlying Cargo executable and forwards its path through the supported `CARGO_*` boundary; other builds do not use this runner. It rejects conflicting network input and does not change Rust's reviewed network policy or allowlist.

Post-build verification reads the dependency file belonging to `libgroot_lib.a`, identifies its actual build-script output, requires Testnet4, and compares the entire static library hash with the file Xcode links. It does not select the newest unrelated compiler/Clippy output. Regressions reject a Regtest linked library even when a newer Testnet4 check exists, and reject substituted library bytes. The startup guard remains the final runtime check.

## Signing and device boundary

The owner explicitly selected a connected, trusted iPhone 13 mini with Developer Mode enabled and confirmed keeping it unlocked. Existing Apple Development credentials and an unexpired Xcode-managed wildcard profile cover that exact device and app identifier. Xcode's automatic **debugging** export uses those existing assets without provisioning updates, device registration, production signing, notarization or publication. Signature, entitlements, bundle identity and device/profile binding are inspected before installation. Private signing keys are neither printed nor exported.

An initial developer-service preparation attempt failed because the phone had relocked; it succeeded after the owner's unlock. Installation uses the distinct identifier and preserves existing app data. Launch/install evidence is not a physical wallet-flow pass.

## Verification and artifacts

All 806 frontend tests in 97 files pass, including the build-handoff and actual-library regressions. Frontend type checking and native-frontend verification are run independently. The Testnet4 iOS archive is rebuilt with the exact-library check before development export/reinstallation. The initial mismatched export/archive remain labeled diagnostic-only in `release-artifacts/ios-testnet4-5.3/`.

Use the [native hardware/iPhone checklist](5.3-native-review.md) for actual observations. Start with launch/relaunch, light/dark, portrait/landscape, scrolling, keyboard/safe areas, large text and VoiceOver. Confirm unsupported operations fail clearly. Do not treat unavailable pairing, phone signing or broadcasting as a working flow; those remain separately gated work.

The evidence directory holds final device/build status, hashes, logs, a source manifest, the unsigned archive and the locally development-signed IPA. An unsigned archive cannot be installed directly. Release validation remains blocked on the required independent reviewed-source record; none of these development steps bypasses that gate.
