# Internal RC14 DMG seal correction

RC13's source app passed `codesign --verify --deep --strict`, but the app on
its mounted DMG failed that check: four Python-runtime symlinks had been
rewritten to absolute paths into the build folder. A tester launched that
DMG copy and every Trezor Model One action returned Groot's bundled-hardware
unavailable error. This was a packaging failure, not evidence about the
Model One PIN retry fix.

The DMG builder now copies signed apps with relative symlinks intact and
checks both the staged app and the app inside the mounted final DMG. An
invalid image is removed on failure. A disposable image made from the RC13
source app passed both checks after this change. RC14's exact final DMG must
pass the same builder checks and a device-free packaged HWI/session probe
before physical handoff.

RC14 changes no wallet/profile/backup/proposal format, signing protocol or
key handling. Re-run the repeated-action Model One trial described in
[the RC13 note](5.3.0-rc13-model-one-retry.md) on the new exact app, including
address verification and health checks without a cable reconnect. Prior
Testnet4 timing samples do not establish RC14 physical acceptance. RC13's
broken DMG must not be used for hardware certification.
