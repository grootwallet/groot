# 0.5.4-rc01 validation record

This record tracks the pre-1.0 version correction and final validation of the
`0.5.4-rc01` maintenance candidate. The exact starting source is
`5818a19caf5603972b006953817d7df613d47335`. The final commit remains pending and
must be recorded below before this document is used as release evidence.

This candidate preserves wallet behavior. It introduces no profile, database,
registry, proposal, backup, descriptor, credential, pairing, or secret-envelope
format change and requires no migration. It changes no BIP implementation,
derivation, transaction format, PSBT format, signing policy, supported network,
or hardware certification claim.

## Required physical acceptance

Automated tests cannot certify cameras, secure storage, USB/HID behavior,
firmware prompts, platform signing, installer ownership, or signer displays.
Before promotion, record exact app commit, OS, device model, firmware, transport,
pass/fail result, and any limitation for each tested case.

- **iPhone:** install the isolated Testnet4 development build on a connected
  device; test create/recover, backup deferral and later verification, lock and
  background transitions, camera denial/retry, pairing cancellation/replay,
  wrong-PIN clearing, exact-PSBT review/signing, restart persistence, and clean
  recovery. No automated result proves Keychain/device-protection behavior.
- **Phone pairing:** certify Standard multisig only. Completed-pair key
  revocation is not implemented; deleting a Groot profile does not revoke a key
  retained by a lost phone.
- **Miniscript/Continuity:** Partner and Family remain Regtest/Testnet4 previews
  using offline PSBT exchange. Test every path before, at, and after maturity,
  mixed input ages, reorg, restart, role rejection, renewal, and independent
  descriptor restoration. Phone enrollment and direct USB signing for delayed
  policies remain blocked. Candidate signer families are not certified merely
  because standard wallet signing works.
- **Windows and Linux:** inspect and install the final native package, then test
  cold/warm HWI discovery, exact account identity, first-address display,
  rejection, signing, disconnect/retry, restart, and broadcast with each claimed
  physical model. Platform signing, Windows device-path limitations, Linux udev
  ownership, and installer lifecycle require their own evidence.

Use disposable Regtest or Testnet4 wallets and bitcoin for these campaigns. Stop
on any network, policy, descriptor, fingerprint, address, recipient, amount,
fee, change, proposal-identity, or signer-role mismatch. Never put recovery
words, credentials, descriptors, addresses, PSBTs, pairing codes, device paths,
or node credentials in public logs or this record.

## Promotion decision

`0.5.4-rc01` remains an internal candidate until the pending automated rows and
the required physical campaigns are complete on the exact final commit. A green
build or generated installer alone does not certify iOS, Windows, Linux,
hardware signers, phone pairing, or Miniscript support.
