## Implementation and safety

ADRs 0098, 0101 and 0102 govern the sealed runtime and one fresh client per
action. Exact original HWI, extracted runtime, app and launcher are verified.
The device's fresh fingerprint and full account xpub must match the saved
candidate before display or signing. Rust rechecks policy, address, reviewed
PSBT, signatures and final context. No state or action is replayed after a
failure. Testnet4/Jade uses HWI's original shared `test` device selector and
keeps the native active-network gate. Model One's PIN request and PIN entry
remain separate; neither is automatically retried.

## Owner retest on RC12

Use the same saved Testnet4 wallet, cable, firmware and one-input proposal.
Time first run and three repeats separately. Keep human PIN/approval time out
of the software intervals. For Jade, Model One and Safe 3 record:

1. **Policy → signer → Check signer:** click to durable result.
2. **Receive → Verify on device:** click to first prompt and displayed address;
   compare the full address.
3. **Sign with hardware:** discovery; select to identify → Ready; signing
   request → transaction review; final approval → Signature added. Review
   amount, destination and fee on-device. Do not broadcast for timing alone.
4. **Model One only:** PIN keyboard appearance and PIN submitted → xpub ready.
   Test one rejected/cancelled challenge and retry by explicit user action.
5. Disconnect, reconnect locked, unlock, and repeat health/identity. Reject
   one device action. Confirm no address, policy or signature success is
   recorded for rejected/mismatched actions.

Capture the exact time, app version/commit, firmware, prompt/error text and
whether another wallet app was open for any Model One failure. Pause if a
verified address or transaction differs from Groot's review.
