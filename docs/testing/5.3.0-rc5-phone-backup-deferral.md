# RC5 phone backup verification deferral

RC4 displayed phone recovery words, then required successful native reconstruction before saving the staged key. Cancelling or postponing that second sheet returned `backup_mismatch` and prevented pairing.

RC5 retains the native word-presentation outcome, matching software creation. Cancelling presentation still creates no signer. Completing presentation may leave verification deferred; the existing encrypted staging and wallet-profile `backupVerified` flag remains false through restart and final policy acceptance. No schema changes, migrations, key replacement or source-pin refresh.

An unverified reminder appears during pairing, on Overview and on the shared-wallet policy page. The policy page offers Verify now and Show recovery words with a fresh app PIN and existing device authorization. The native loader rejects coordinator/watch-only roles and checks the decrypted phone account against the selected wallet's fingerprint, xpub and derivation before displaying or checking words. Wrong PIN, cancelled/mismatched verification and errors cannot mark the backup verified. Only a successful native check updates the existing registry flag atomically. Existing software-wallet behavior and background locking remain intact.

Regression evidence includes staging/resume coverage for both verification states, native account-identity checks, and synthetic desktop/mobile light/dark UI flows for deferred pairing, wrong PIN, cancellation and successful later verification. Exact executions and packages are recorded with the candidate's local proof artifacts; browser evidence never proves device authorization or recovery. Physical native word entry and authorization require the owner and must not be captured. Public release review, hardware certification and the reviewed-source gate remain required.
