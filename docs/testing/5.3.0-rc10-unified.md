# Groot 5.3.0-rc10 unified candidate

Internal rehearsal only. This combines the two original feature tracks and later
fixes on `codex/5.3-unified-rc10`; main is not merged. Version numbers RC3–RC9
already identify earlier candidates, so the next candidate is RC10.

## Source and branches

The corrected originating chats are **Groot full code quality audit and fix…**
(`01a14dea-9e51-7211-83fe-b8ed06a24dc2`) and **Groot 5.3 Mobile**
(`01a14422-dd13-71f2-8095-67534deebedc`). Their implemented RC8 baseline is

A history-only merge records that already-ported lineage while preserving the newer candidate tree.
The dirty primary checkout is preserved separately. Existing wallet/profile,
backup, credential, notification and proposal formats remain compatible.

At integration, fresh `origin/main` was `733bc513`, with zero open GitHub PRs.
There were 13 local branches not ancestral to main, or 14 including this new

- Existing internal Testnet4 iOS software-wallet, backup/recovery, phone pairing
  and standard-multisig QR signing work, with the desktop corrections through RC8.
- Fixed Partner/Family test-network setup, named delayed paths, role-bound
  signatures, persisted path selection and primary renewal (ADR 0100).
- Coldcard Mk4 Testnet4 pre-extracted HWI runtime, with complete runtime/app
  verification and fresh device/account proof (ADR 0098). No hardware-state cache.
- Remove the 0.01 BTC recipient/debit ceiling; retain the 100,000-sat Mainnet fee
  protection, monetary bounds and actual final-PSBT checks. Show specific
  allowlisted policy errors in EN/FR/ES (ADR 0099).

Miniscript enrollment and Android secret operations remain unavailable.
Public release requires independent review and exact-source authorization.
The Mk4 host-startup benchmark is not proof of physical signing speed.

## Physical acceptance sequence

Use Testnet4 and disposable test funds. Record exact candidate, model, firmware,
network, operation, outcome and host elapsed time; exclude private unlock and
human trusted-display review time. Never record recovery words, credentials,
full addresses, xpubs, PSBTs or device identifiers in timing logs.

1. **Mk4 connection first:** quit the older candidate yourself. Connect only the
   Coldcard Mk4, close vendor apps, unlock privately and enable USB. Open this
   candidate with its Testnet4 launcher. Confirm version/network. Measure from
   connect to discovery, then selection to identified signer, then one saved-
   signer health check. Repeat identification five times without changing the
   wallet. Separate initial and repeated timings; stop on timeout or wrong state.
2. **State transitions:** lock Mk4, retry, unlock, disconnect/reconnect, cancel a
   prompt and select a device outside the wallet. Each must show an accurate
   actionable state; reconnect must prove the full account again. Compare RC9
   or RC8 using the same profile and operations, one app at a time.
3. **Standard multisig policy and address:** connect the other actual members
   (phone/Ledger only if they are in the chosen wallet). Register/import the
   actual policy as required. Compare the complete receive address on each
   trusted display; discovery is not policy verification. Test rejection and retry.
4. **Phone:** native create/recover/verify backup; desktop-led pairing; matching
   policy/first address; cancel/resume; revoke/re-pair; lock/restart both apps.
   No secret appears in QR or webview. Desktop remains usable if the phone is lost.
5. **Small standard transaction:** review actual recipient, fee and change on
   desktop, phone and hardware. Collect signatures, restart between signatures,
   reject a different PSBT, then broadcast only the reviewed Testnet4 payment.
   Record identity/policy/signing overhead separately from human approval time.
6. **Amount/error regression:** prepare a Testnet4 payment above 1,000,000 sats
   using sufficient disposable coins. Preparation must succeed if otherwise
   valid. Check clear unavailable-node, wrong-network and invalid-amount errors.
   Mainnet fee-limit protection is validated in native tests; this rehearsal is
   not authorization to broadcast a Mainnet transaction.
7. **Fixed Miniscript:** use external offline PSBT tools/signers that actually
   support the exact descriptor. For each template, verify roles and both first
   descriptors/addresses, export backup and restore into a clean disposable
   profile. Exercise primary payment and renewal; verify the fresh owned output.
   Every delayed path requires its exact mature coin. Fixed delays are long:
   use isolated Regtest for before/at/after and reorg tests rather than claiming
   a brief Testnet4 session proves maturity. USB/phone Miniscript remain blocked.
8. **Final regression:** multi-wallet lock/switch, receive labels and unused-
   request discard, fee failure/custom rate, frozen coins, reconnect/offline
   retry, RBF/CPFP, QR/file rejection, restart and recovery. Check desktop/mobile
   EN/FR/ES, both themes and keyboard-safe bottom actions.

Any wrong signer/recipient/path, lost partial signature, stale-state bypass or
failed restore blocks GA. Hardware/phone timing and full acceptance are still
human-run evidence; no automatic main merge is planned.

## Owner-reported Mk4 trial and follow-up

On 2026-10-20 the owner tested packaged RC10 `ce9dd919` with a Coldcard Mk4 on Testnet4: passive discovery appeared instant, health check about 5 s, selection-to-identified 6.22 s, request-to-device transaction review 9.5 s, and signing return 4.92 s for one input. These are single manual observations; firmware and exact timing boundaries were not recorded, and no matching baseline/repetition or full threshold/broadcast/recovery campaign is claimed. The initial missing-device result was explained by connection to a charger instead of the computer. Policy import used microSD outside Groot. The detailed incomplete worksheet is kept in ignored local certification output.

The screenshots exposed two independent defects: a failed health check recoloured the policy-import badge, and one missing Core fee target suppressed every estimate. Read-only RPC checks confirmed an available 144-block estimate but no 6/2-block estimate. Follow-up source preserves each available fee target, leaves missing targets disabled, keeps a validated custom rate, separates policy/health colour and labels file acknowledgement Import recorded. Payment, signer-health and policy-review errors compose existing WarningNotice. Source changes after `ce9dd919` are for the next candidate; the immutable RC10 packages are not replaced or relabelled. Existing profiles/backups/proposals remain compatible, with no dependency or reviewed-source-pin change.
