# RC4 separate mobile setup with an existing wallet

The RC3 session monitor omitted mobile setup from its pause predicate, and startup omitted it from the locked-wallet redirect exception. An existing locked wallet could therefore redirect phone pairing/recovery/watch-only import to Unlock.

RC4 uses one exact mobile setup route predicate in startup, session monitoring and sync cancellation. The selected wallet stays locked; signing and ordinary wallet pages retain their lock guards. Native background locking, backup/device authorization and the pairing protocol are unchanged. No wallet or proposal format changes, resets or migrations.

Regression coverage starts with an existing locked profile, follows Add another wallet → Add wallet → Connect desktop app, advances the monitor clock and checks that the scanner remains reachable. Direct startup covers all three setup routes. Unit checks prove that returning to signing resumes locked-session handling. Browser fixtures prove orchestration only; physical pairing still needs the owner’s native backup and authorization steps.

The release-source review gate remains unchanged. Existing desktop signer drafts must survive installation; do not discard or recreate their hardware keys. Expired invitations may be renewed without changing the draft.
