# 5.3.0 internal Mainnet UI follow-up

On unsigned RC16 (`3c461075`), the owner observed nearly instant health, address, identity and signing presentation for Model One, Safe 3, Nano S Plus, original BitBox02, Nova and Jade Classic. Coldcard Mk4 actions felt reasonably fast, about 2–3 seconds. No controlled Mainnet timing table or negative/restart matrix was supplied; these observations support an internal speed result, not GA certification.

The same trial showed two visible defects. Hardware account-import errors touched the preceding Rescan devices card. A generic Jade read failure gave only unlock/other-app advice when Jade was still configured for Testnet4 and Groot was on Mainnet. RC17 adds route-owned space above the existing shared `WarningNotice` and makes a generic Jade error suggest checking its selected Bitcoin network. It does not claim the network is wrong unless HWI returns the typed wrong-network error.

After approving a new wallet's managed-node genesis scan, Overview could still show **Approve wallet-history scan**, **Scan settings**, an unverified zero balance and **Wallet history not verified**. The shell-owned scan now reports its in-flight wallet to Overview. Overview polls the native scan status and shows startup/progress plus loading placeholders until verified state is available. Failed/interrupted scans retain their existing explicit retry. This changes no consent decision, scan settings, node endpoint, wallet data or recovery checkpoint.

Browser fixture checks cover the Jade error/retry and notice spacing, plus approved scan progress at desktop and mobile sizes. Physical retest is still needed for the two affected device messages and one real managed-node first scan. The unsigned internal RC17 is for that retest; exact-candidate GA release gates remain in the Mainnet checklist.

RC16 CI also exposed two cross-platform test failures. The HWI process-failure test now uses its own executable fixture instead of assuming Linux `/usr/bin/false` is a non-symlink. The existing tooltip now measures after focus-triggered scrolling and tracks later scroll/resize changes, keeping its receive-label gap aligned on desktop and mobile browsers. Neither change alters hardware protocol or wallet data.
