# Groot 5.2.0-rc02 — what to test

Quit rc01, install rc02, and confirm **5.2.0-rc02** in the app. Start with these checks; use an empty test wallet for deletion.

| Test           | Do this                                                                                                                            | You should see                                                                                                                                                                              |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First scan     | Create a wallet and click **Approve and scan**.                                                                                    | Scan starts; the approval closes and progress appears. No credential error.                                                                                                                 |
| Own node       | On another first scan, click **Set up my own node**.                                                                               | Bitcoin Core connection dialog opens directly, with local/custom/Groot choices where available.                                                                                             |
| Scan failure   | Try an unavailable node, then fix its connection and retry.                                                                        | A normal error box and enabled retry; no stuck dialog.                                                                                                                                      |
| Creation       | Create software, hardware or multisig wallets.                                                                                     | No checkbox offering another wallet’s network setup. Recovery creation stays disabled, with a description and **Coming soon**.                                                              |
| Labels         | Import the original Groot JSONL into your restored 2-of-3 wallet.                                                                  | Address labels import. The three xpub records say **signer keys matched**, not unsupported. Current signer names are kept.                                                                  |
| Change PIN     | Hardware wallet → Settings → Security → **Change app PIN**. Try a wrong current PIN, then the correct PIN plus a new matching PIN. | Wrong PIN changes nothing. Success locks that wallet; old PIN fails and new PIN unlocks. Its node connection still works. Repeat with multisig. Software wallets have no Change PIN option. |
| Receive policy | Try to receive before verifying enough signers.                                                                                    | Standard error box and a blue outlined **Open Policy** action. Verify the signers, return, and generate the address.                                                                        |
| Policy address | During Nova policy registration, expand the first address, then **Address details**.                                               | Same derivation rows/font as Receive, including the path and index.                                                                                                                         |
| Delete         | Empty software wallet → Delete. Enter passphrase and `DELETE`.                                                                     | Separate, spaced backup checkboxes appear after `DELETE`. Both are required. Deletion stays responsive.                                                                                     |

Still worth checking from rc01: Tab creates multiple unknown-source labels; addresses/xpubs group into four characters with a short final block; unlocked hardware candidates use amber **Select to identify**; descriptor copy/QR/PDF shows one descriptor for receive and change.

Different xpub ordering and checksums in Sparrow can be normal with `sortedmulti`: it sorts the derived public keys. Compare receive **and change** addresses at indexes 0, 1 and a later index. They must match; the checksum itself need not.

Report the failing step and screenshot. No recovery words or PINs are needed.

File → View wallet files is tracked in #115 and is not implemented. Refactoring proposals are in `docs/code-quality-plan-2026-09-06.md`. This is an internal ad-hoc signed macOS Apple silicon build, not a public release.
