## Repeated-action defect and change

On RC12, Model One sometimes showed “Trezor unavailable” after a prior
successful action. Clicking **Try again** did not recover; only physically
reconnecting did. The screenshot alone does not establish whether HWI returned
“already unlocked” during PIN submission, a stale scan capability was reused,
or the USB transport failed. The follow-up handles only two concrete safe
cases: HWI's typed `-11` already-unlocked PIN submission proceeds to the
existing fresh full-account identity check, and PIN-error retry discards the
old selection and performs a new passive scan. Wrong PIN, disconnect and
other HWI errors remain failures. No unlocked device state is cached as proof.

Acceptance requires a new exact-candidate physical test: keep Model One
plugged in; perform xpub import, address verification, health, identification
and signing in sequence, then repeat the address and health actions without
unplugging. If an error appears, use **Scan again**, select the signer and
record whether that recovers without reconnecting. Also reject one PIN
attempt and one on-device action, then verify no false address, policy or
signature success was recorded. Record the precise error code or sanitized
app log outcome if the fault repeats. Mainnet and other physical model checks
do not inherit a pass from this Testnet4 trial.

There is no profile, wallet, backup, registry or proposal format change and
no migration. The BIP impact assessment is in `docs/bip-support.md`.
