# Internal RC15 Model One repeated-action retest

RC13's typed already-unlocked PIN handling did not fix the physical repeated-action failure. RC14 restored the mounted DMG seal, but the owner then observed a failed saved-signer health check, a successful PIN unlock and fast address verification, followed by “Trezor unavailable” when starting transaction signing. The PIN dialog replaced the native error detail with generic connection advice, so that screenshot did not establish which hardware stage failed.

The passive Model One row still requested `prompt_pin` after a successful PIN exchange. RC15 treats that short-lived observation only as permission to try the normal live account proof first; it is never accepted as identity or authorization. The multisig signing route also avoids a second PIN prompt after the same scanned signer was identified. A saved-signer health check now opens the existing bounded PIN matrix when the selected Model One is locked. The PIN error display preserves Groot's sanitized native error text so a repeated failure can distinguish a bundled-runtime problem from a missing device.

This change does not modify persisted data, the pinned HWI executable, device firmware, BIP paths, descriptors, PSBTs, signing policy, or final signature checks. Existing profiles remain compatible. Automated tests can prove routing and error presentation, but cannot certify the physical USB transition. The owner should test on the exact RC15 Testnet4 build without unplugging between: saved-signer health check, address verification, identification, signing, and repeated health/address checks. Record whether PIN appears, whether **Scan again** recovers, and the complete safe error text if it fails. Only after that Testnet4 sequence passes should the same seven-device speed campaign move to Mainnet; each network and model needs its own observed result.
