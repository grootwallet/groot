# Groot 5.3.0-rc11 hardware performance rehearsal

Internal Testnet4 candidate on `codex/5.3-unified-rc10`; main remains unchanged.
RC10 artifacts remain immutable rollback. Source, runtime digest and exact build
results belong in packaged `BUILD-INFO` and `RESULTS.txt`. No persisted format or
BIP support changes; see ADR 0101.

## Changes

- Extend sealed runtime startup acceleration to Ledger and BitBox02 Testnet4.
- Prove the fresh fingerprint and full account key, then display/sign using one
  isolated connection per operation. No identity/unlocked-state cache.
- Retain policy, device approval, cancellation, signature and final native checks.
- Include the RC10 feedback corrections: policy import acknowledgement independent
  of failed health, reusable error notices, and independent nullable Core fee
  targets. A connected node can legitimately lack a particular fee estimate;
  use a valid custom rate for that target. No invented fallback rate.
- Preserve the unified mobile, Miniscript and cap-removal source baseline.

## Owner baselines and 50% targets

Single manual RC10 samples, not controlled medians or certification. These
numbers define retest goals; they are not claimed RC11 results.

| Interval                    | Mk4 baseline / target | Ledger Nano S Plus baseline / target  | Original BitBox02 baseline / target |
| --------------------------- | --------------------- | ------------------------------------- | ----------------------------------- |
| Health                      | ~5 / ≤2.5 s           | 8.29 / ≤4.15 s                        | 11.18 / ≤5.59 s                     |
| Identification              | 6.22 / ≤3.11 s        | 5.59 / ≤2.80 s                        | 8.97 / ≤4.49 s                      |
| Address/policy presentation | not measured          | 16.45 / ≤8.23 s                       | 17.35 / ≤8.68 s                     |
| Transaction presentation    | 9.5 / ≤4.75 s         | 11.34 / ≤5.67 s after policy approval | 13.27 / ≤6.64 s                     |
| Final approval to signature | 4.92 s, one input     | ~0.5 s                                | almost instant                      |

Ledger first policy prompt was 13.85 seconds; initial signing prompt was instant.
Keep those separate from the 11.34-second policy-approval-to-transaction interval.
Human review and approval time must not count toward software latency.

## Repeat on each of the three devices

1. Quit RC10 yourself, then use the RC11 Testnet4 launcher. Confirm **5.3.0-rc11**
   and its build commit. Keep only the tested signer connected by a data cable;
   close vendor wallet apps. Use the same saved Testnet4 wallet and firmware.
2. In **Policy**, open that signer and click **Check signer**. Time click to inline
   result. Record any unlock, pairing or policy prompt separately.
3. Open the same prepared disposable payment, then **Sign with hardware**. Time
   dialog open to **Select to identify** (discovery), then click the signer and
   time to **Ready** (identification). Identification alone must not sign.
4. For address verification, use the wallet's receive address **Verify on device**
   action. Measure request to first device prompt, and each final policy approval
   to address display separately. Compare the full address before approving.
   Coldcard policy import remains on microSD/VirtualDisk outside Groot.
5. For the same one-input transaction, time the signing click to first prompt,
   final policy approval to transaction review, and final transaction approval to
   **Signature added**. Verify outputs/amount/fee on the device. Broadcasting is
   unnecessary for this measurement.
6. Repeat timed steps three times after the first run; report first run separately
   and the median of the three warm runs. Keep the same input count and wallet.
7. Reject one device request: no signature or policy verification may be recorded.
   Cancel a pending operation, then retry once; no action may replay automatically.
8. Disconnect, run health, record duration/message. Reconnect locked, repeat, unlock
   privately and repeat. Confirm the saved policy acknowledgement retains its own
   correct status and successful reconnection does not require changing pages.

Share device/firmware, each interval, outcome and any prompt/error text. Stop on
an address/transaction mismatch. Nova, Safe 3, Model One and Jade remain a later
separate physical test round; these results do not certify them.
