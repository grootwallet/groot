# 5.3.0-rc2 mobile keys — candidate test record

Refs #6. This records implementation and ongoing verification, not public release authorization or a completed mobile certification. Source is the current 5.3 working tree until the frozen candidate identity is recorded below.

## Implemented scope

- Retained BIP129 QR pairing, signer proof, full public policy validation, resumable phone staging/cancel, exact-policy recovery and signature-only PSBT round trip, ported from `85e794a28a222a6591cb080b6a23efcbbc1582d2`.
- Native iOS software key generation/recovery/backup verification and Testnet4 signing; new iOS secret files require both the local credential and device-authorized Keychain key.
- Multisig phone backup verification before saving a signer; PSBT review derives amounts, recipients, verified change, fee, estimated size/rate, locktime, RBF and existing signatures in Rust.
- Worker scheduling, queued wallet-selection checks, background locking, bounded/localized QR retry, and unchanged accepted-broadcast persistence/reconciliation safeguards.
- Component-scoped CSS and shared controls. Native phone choices are placed early in the existing menu. Settings theme changes now update the shell theme indicator too.
- Desktop authority for shared/watch-only receiving; standalone phone software wallets retain local labelled receiving. No general metadata sync, relay or seed transfer.

## Current evidence

- Full frontend suite: 855 tests passed at the last completed run; later changes require final rerun.
- Integrated native suite: 562 library tests and 3 integration tests passed, 15 library/4 Core tests ignored at that run; later changes require final rerun. Strict host Clippy also passed before later changes.
- Full isolated real-Core harness: 9 native scenarios plus 4 descriptor/multisig integration cases passed, including actual phone-key signing, exact desktop merge, second signature, finalization and broadcast. This did not use the physical phone or an existing funded profile.
- Physical iPhone trial 02: the corrected 5.3.0-rc2 app installed with verified existing development signing, exact Testnet4 native library binding and Apple bundle build 530002. Native software generation reached its real privacy sheet; cancellation passed without revealing words or saving a wallet.
- The first camera/navigation test encountered an XCTest off-screen hit-point failure. Its scrolling helper was corrected; the next run is currently waiting for the phone to be unlocked. No successful physical pairing/signature exchange is claimed yet.
- The initial generated archive accidentally bundled `libapp.a`, making it 940 MB and timing out over Wi-Fi. A tracked preparation step and post-archive rejection now prevent build-only static-library resources. Corrected unsigned app size is about 162 MB with debugging sections stripped before development signing. Initial diagnostic packages are not the final candidate.

The desktop internal builder now uses a distinct `Groot RC.app` name and `app.groot.wallet.internal` storage identity, with a camera-only entitlement for QR rehearsal. The production app/configuration and existing profiles are not replaced.
