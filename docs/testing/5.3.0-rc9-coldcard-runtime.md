# RC9 Coldcard runtime acceptance

RC9 is an internal Testnet4 Coldcard Mk4 packaging experiment under ADR 0098.
It starts from clean RC8 source `067f83722895d236eb0d4ab88e42994471fb97fe`.
The package's generated `BUILD-INFO` binds its exact RC9 source, executable,
unchanged HWI 3.2.0 digest and extracted-runtime manifest digest.

## Host acceptance

- Verify the complete app signature, original pinned HWI digest and every
  extracted-runtime file/symlink. Two independent preparations must generate
  identical payload manifests. Rust must accept that real generated payload.
- Reject modified/missing/extra files, writable payloads, path traversal,
  substituted/escaping links, malformed archives and mismatched manifests.
- Compare device-free version launches with ordinary extraction and the sealed
  payload. Report first launch separately; warm p50/p95 excludes that sample.
  These timings establish no USB, identity, display, registration or signing pass.
- Run mandatory validation, frontend checks and relevant Rust/packaging checks.
  Preserve and report the existing reviewed-source gate failure; never refresh
  pins or treat an internal package as public release authorization.

## Owner operated physical acceptance

Use the same existing Testnet4 wallet when comparing RC8 and RC9. Keep its data
and all signer/pairing settings unchanged. Close vendor apps and connect only
the Mk4 initially. Record exact firmware and package identity without retaining
keys, addresses, fingerprints, device paths, PSBTs or credentials in evidence.

1. Unlock Mk4 privately and expose USB. Time passive discovery separately.
2. Time saved-signer identification and health. Confirm a different account or
   signer fails membership checking without changing the wallet.
3. Verify a BIP84 receive address on the device; compare its complete value.
4. For BIP48, compare the policy and receive address. If policy import is still
   required, confirm the existing specific setup error; do not treat that error
   as a successful display benchmark. Policy import remains an explicit owner
   action, not an automatic performance step.
5. Reject a review, retry unchanged, unplug/replug and rescan, cancel and reopen.
   Confirm stale actions cannot update the wallet and other devices stay untouched.
6. On a separately authorized disposable funded proposal, compare signing with
   human review time recorded separately. Validate outputs, amount, fee and
   change on Mk4; require the intended signature count and unchanged proposal.
7. Restart and confirm existing wallet/proposal/history state. Roll back to RC8
   if necessary; profiles and proposals require no conversion.

The current Coldcard/iPhone/Ledger policy cannot use BitBox02 as a replacement
signer. RC9 changes neither phone signing nor the remaining six hardware paths.
Physical acceptance remains pending until the owner completes these steps.
