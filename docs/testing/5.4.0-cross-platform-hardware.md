# Groot 5.4.0-rc01 Windows/Linux human test

These builds are unsigned, internal and Testnet4-only. Use disposable wallets
and Testnet4 bitcoin. Never enter a real recovery phrase.

## Install

### Windows 11 x86-64

1. Check the downloaded MSI or setup EXE against `SHA256SUMS`.
2. Install it. Windows may warn because this internal candidate is unsigned;
   confirm only when the digest matches the supplied evidence.
3. Open **Groot 5.4 Testnet4** and confirm the app says `5.4.0-rc01` and
   Testnet4 before creating anything.

### Ubuntu 24.04 x86-64

1. Check the DEB against `SHA256SUMS`.
2. Install the DEB with the normal graphical installer.
3. Install the signer vendor's current Linux udev rules if the device is not
   visible. Log out/in or reconnect the signer after adding rules.
4. Confirm Groot says `5.4.0-rc01` and Testnet4.

## One-signer basics

Do this with each physical model you have. Record the exact model, firmware,
Bitcoin app version where relevant, connection type, operating system and
result. Test only one connected signer at a time first.

1. Initialize and unlock the signer using its own trusted screen.
2. In Groot, create a **hardware wallet**, then select **Scan**.
3. Confirm the correct model appears once. If it does not, reconnect it and
   scan once more; record the failure instead of installing an unverified HWI.
4. Select it and confirm Groot reads its fingerprint and account key.
5. Reveal the first receive address and verify the complete address on the
   signer screen. Stop if one character differs.
6. Send a small amount of Testnet4 bitcoin to that address and sync Groot.
7. Make a small outgoing payment. On the signer, verify destination, amount,
   fee and change. Reject it once and confirm Groot stays safe and retryable.
8. Repeat and approve. Broadcast, confirm the transaction appears, restart
   Groot, unlock, and confirm the wallet and transaction are still correct.
9. Disconnect during one scan or review. Confirm Groot shows a useful retry
   state, then reconnect and complete the action.

Start with Ledger Nano S Plus, BitBox02 Bitcoin-only/Nova, Coldcard Mk4 and
Jade. Linux can also test Trezor Safe 3/Model One. Windows currently discovers
HID-capable Trezors only; a missing Safe 3 is an expected certification gap,
not permission to weaken device-path checks.

## Standard multisig and phone pairing

1. Create a new **Standard 2-of-3** wallet with two physical signers and the
   paired Testnet4 iPhone as the third signer.
2. Compare the policy and first receive address on both hardware signers.
3. Pair the phone by scanning Groot's QR. On the phone, confirm the wallet name,
   2-of-3 threshold and all three signer fingerprints before accepting.
4. Fund the first shared Testnet4 address with a small amount.
5. Create one payment on desktop. Reject the first phone review, then retry.
6. Verify recipient, amount, fee and change on the phone; sign and return the QR.
7. Add one physical signature, finalize, broadcast, restart both apps and
   confirm the shared wallet still opens correctly.

Phone pairing is for **Standard multisig only**. It must not appear as a signer
option for Partner or Family delayed policies.

## Partner/Family Miniscript preview

1. Use Regtest or Testnet4 and disposable keys only.
2. Create one Partner or Family preview and confirm Groot clearly labels it
   experimental and shows the delay and required signer roles.
3. Export the primary-path PSBT and sign it through an offline workflow. Import
   it and confirm Groot identifies the primary path.
4. Create a delayed-path proposal. Before maturity, confirm finalization is
   blocked. After the required Regtest blocks or Testnet4 maturity, sign the
   exact required path, import it and confirm the destination/fee again.
5. Test renewal to a fresh owned output and verify the new address belongs to
   the same policy.

Direct USB Miniscript signing is not certified. Candidate families are Ledger,
Jade/Jade Plus and BitBox02/BitBox02 Nova only when the exact
model/firmware/transport succeeds in the offline PSBT test. Coldcard, Trezor and
the phone signer are unsupported for delayed policies in this preview.

## Report only these facts

- OS and version
- Groot filename and SHA-256
- signer model, firmware and connection type
- pass/fail for scan, identity, address, reject, sign, broadcast and restart
- approximate first and second scan/signing times
- the visible error code or short message for failures

Do not include seeds, descriptors, xpubs, fingerprints, addresses, PSBTs,
transactions, node credentials or screenshots containing wallet data.
