# 5.3.0-rc3 mobile first-open corrections

Internal Testnet4 follow-up to RC2. The candidate retains its wallet formats, key protection, QR protocols and source-review gates.

- Native mobile onboarding has no fixed version footer; build information remains in Settings. Its scroller begins below the system status area and reserves only safe bottom spacing.
- Overview presents one missing-node notice, then the separate backup notice, without negative margins. The compact header avoids excess empty space.
- First-history approval checks mobile RPC configuration before enabling the action. A local desktop Core/cookie or incomplete remote configuration requires setup. Groot managed access is Mainnet-only; this candidate does not provision a Testnet4 service or expose a desktop RPC listener.
- Existing desktop privacy approval, native URL/TLS/Tor/authentication checks and explicit history consent remain unchanged.

Browser fixtures verify both themes, no welcome overflow, footer absence, notice separation, blocked scan approval and the node-setup handoff. They do not prove remote connectivity, physical key custody, signing or recovery. Recheck the exact frozen app on the connected iPhone. The owner-provided recovery-word and passcode captures must never enter evidence bundles.

Miniscript remains a separate feature integration. Continuity creation, direct USB delayed-policy operations and public-release/source pins remain gated.
