# Mobile key audit — 5.3

Date: 2026-10-18. Tracking: [issue #6](https://github.com/grootwallet/groot/issues/6), verified open. This is a gap assessment with fresh tests, not completion or certification of mobile signing.

## Findings

| Capability                       | Installed Testnet4 iPhone foundation                                                                 | Retained coordination branch                                                                                                     |
| -------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Phone software wallet            | Choice is shown; native generation is rejected before entropy. Recovery/signing also remain guarded. | Shared software domain and native iOS presentation/entry exist; physical create/verify/restore/sign acceptance incomplete.       |
| Phone multisig signer            | No pairing routes, contracts or commands.                                                            | BIP48 signer, BIP129 QR setup, policy validation, restart staging and exact-policy recovery exist.                               |
| QR signing                       | Absent.                                                                                              | Actual PSBT review/sign and desktop signature-only merge pass a funded native Regtest test. Not a physical-phone signing result. |
| Device protection                | No mobile key can be created.                                                                        | Explicitly `argon2id_pin_envelope_testnet_only`; device-bound Keychain/user-presence wrapper is missing.                         |
| General metadata synchronization | Absent.                                                                                              | Public policy and signer manifest transfer exist. Complete live labels/history sync and relay are not implemented.               |
| Android                          | No certified artifact or native secret workflow.                                                     | No Android secret UI/platform protection certification.                                                                          |

The installed mobile UI misleadingly offers software creation before its native capability rejection. Do not interpret the menu as implemented support. Re-enabling buttons or deleting the native guard cannot complete the missing trusted boundary.

The owner intended both phone-held software wallets and an independent multisig phone key. [ADR 0093](../adr/0093-restore-mobile-key-delivery-scope.md) corrects the earlier watch-only scope; the [revised implementation plan](../mobile-5.3-plan.md) orders protection, recovery, software wallet, pairing and signing acceptance. QR transfers public keys and metadata, not private seeds. Phone multisig recovery in the retained branch uses 24 words with an empty BIP39 passphrase and a local PIN; current software wallets use the exact BIP39 passphrase. These cannot be silently interchanged.
