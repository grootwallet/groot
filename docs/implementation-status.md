# Current implementation status

This page describes 5.3 development from the shipped `5.2.0` baseline at `733bc513d5fe570a1ceb27d8815ed00a4b2a0459`. The owner's handoff records its signed/notarized GitHub publication; this branch preserves that release and does not extend ADR 0088 authorization to mobile or modified source. The [5.3 plan](mobile-5.3-plan.md) owns the current mobile scope.

**Native** means implemented behind Rust/Tauri. **Fixture** means browser demonstration only. Neither is physical-device certification. Exact release/device evidence belongs in the [Mainnet checklist](mainnet-release-checklist.md) and [hardware certification](hardware-certification.md).

| --------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Unavailable or experimental

- Timelocked Recovery and Assisted recovery creation are disabled with **Coming soon**. Existing delayed-policy profiles remain compatible; native compiler/spend tests are not a release claim.
- Decaying/expanding policies are experimental foundations, not supported creation paths.
- Payjoin V2 recognizes requests and rejects unsupported fallback; sender/receiver sessions and transport are not implemented.
- Experimental Windows/Linux x64 packaging is Signet-only, without bundled HWI, native seed UI or passive USB discovery. Builds/CI do not certify physical platforms. iOS and Android public releases are not certified. Passive USB discovery is macOS-only; Windows production HWI verification fails closed.
- The unified 5.3 candidate adds test-network Partner/Family setup, explicit named delayed-path selection, primary renewal, role-bound signature collection and persisted-PSBT path recovery (Refs #17, ADR 0100). Browser and native checks are implementation evidence; exact-candidate real-Core results, physical acceptance and independent review are tracked in the RC10 record. Mainnet Continuity, direct USB Miniscript and phone enrollment into these templates remain blocked.
- Internal iOS Testnet4 candidate code now restores QR pairing, native phone backup/recovery, new device-protected software/phone-signer keys and exact-PSBT signing under ADRs 0093–0096. Physical full-flow acceptance and independent review remain incomplete; this is not public mobile support. Android secret UI/platform protection, Mainnet mobile and phone continuity/Miniscript enrollment remain outside the enabled scope. See the [candidate record](testing/5.3.0-rc2-mobile-keys.md).
- No cloud backup, custodial key service, Lightning, Taproot wallet, or hosted remote signing service is implemented.

## Maintaining this page

Keep one row per capability. Update it when scope or evidence changes; do not append release diaries or historical test totals. Standards and limitations belong in [`bip-support.md`](bip-support.md). Release authorization remains exact-commit scoped.

Documentation cleanup has **no BIP, API, schema, dependency or runtime impact**. It corrects stale descriptions without extending support.

RC6 replaces repeated iOS key-access prompts with Groot credential authorization while retaining device-bound v6 files and original legacy Keychain items (ADR 0097). Mobile safe scroll bounds, compact setup copy, phone QR connection labels and completed-camera cleanup have dedicated browser regressions. Physical verification remains candidate-specific.

The sealed internal multi-network RC16 uses the extracted HWI runtime for Coldcard, Ledger, both BitBox02 models, both Trezor models and Jade on Testnet4 and Mainnet, with fresh full identity proof and at most one action per isolated connection (ADRs 0098/0101/0102/0103). Trezor PIN requests remain separate device challenges; Jade uses HWI's shared test-network selector only on Testnet4. Trusted display, policy gates, cancellation and final native checks remain. The owner reports that Model One repeats work on Testnet4 and that all seven Mainnet signers feel nearly instant, with Coldcard Mk4 actions around 2–3 seconds. Those qualitative Mainnet observations do not replace exact timing, negative/restart checks or signed GA certification. The production Mainnet build remains on the existing helper path until the final release campaign. RC17 corrects first-scan progress and hardware-import error presentation without changing wallet or signer authority.

RC18 prepares a canonical-identity, ad-hoc owner candidate with the same sealed fast runtime and unchanged wallet formats. The owner passed the three RC17 follow-up UI checks. Its artifact remains distinct from a Developer ID-signed and notarized GA package.
