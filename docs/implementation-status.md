# Current implementation status

The released desktop baseline is [v5.3.0](https://github.com/grootwallet/groot/releases/tag/v5.3.0), commit `6a39bf50b2a6a042354b43369765a9af2174d061`, published 2026-10-23. The macOS Apple-silicon release includes the sealed fast runtime for the seven named standard hardware models under ADRs 0104/0105. Publication is separate from physical acceptance of the internal Testnet4 iOS and Continuity previews. Changes after this commit are development source, not a replacement release.

`0.5.4-rc01` adds internal Testnet4-only Windows x86-64 and Linux x86-64 packaging under ADR 0106, with the corrected pre-1.0 version scheme recorded in ADR 0107. Exact HWI 3.2.0 platform artifacts are checksum-pinned and unpacked into a runtime Groot verifies before use. Cached OS HID/USB/serial inventory is wired without opening signers; Windows deliberately omits unverified WebUSB Trezor path translation. Native package inspection and physical signer testing remain required before public support. Final v0.5.4 and Mainnet distribution are not authorized.

**Native** means implemented behind Rust/Tauri. **Fixture** means browser demonstration only. Neither is physical-device certification. Exact release/device evidence belongs in the [Mainnet checklist](mainnet-release-checklist.md) and [hardware certification](hardware-certification.md).

## Unavailable or experimental

- Timelocked Recovery and Assisted recovery creation are disabled with **Coming soon**. Existing delayed-policy profiles remain compatible; native compiler/spend tests are not a release claim.
- Decaying/expanding policies are experimental foundations, not supported creation paths.
- Payjoin V2 recognizes requests and rejects unsupported fallback; sender/receiver sessions and transport are not implemented.
- Experimental Windows/Linux x64 packaging is Testnet4-only, with a pinned unpacked HWI runtime and passive HID/USB/serial inventory. Windows deliberately omits unverified WebUSB Trezor path translation. Builds and driver probes do not certify physical models, native seed UI remains unavailable there, and the unsigned packages are not public releases. iOS and Android public releases are not certified.
- The unified 5.3 candidate adds test-network Partner/Family setup, explicit named delayed-path selection, primary renewal, role-bound signature collection and persisted-PSBT path recovery (Refs #17, ADR 0100). Browser and native checks are implementation evidence; exact-candidate real-Core results, physical acceptance and independent review are tracked in the RC10 record. Mainnet Continuity, direct USB Miniscript and phone enrollment into these templates remain blocked.
- Internal iOS Testnet4 candidate code now restores QR pairing, native phone backup/recovery, new device-protected software/phone-signer keys and exact-PSBT signing under ADRs 0093–0096. Physical full-flow acceptance and independent review remain incomplete; this is not public mobile support. Android secret UI/platform protection, Mainnet mobile and phone continuity/Miniscript enrollment remain outside the enabled scope. See the [candidate record](testing/5.3.0-rc2-mobile-keys.md).
- No cloud backup, custodial key service, Lightning, Taproot wallet, or hosted remote signing service is implemented.

## Maintenance and evidence

The current branch separates native profile lifecycle, notification delivery and recovery commands. Frontend helpers own Settings reads, request lifetimes, node forms and acceleration quotes. Phone review requires complete previous transactions and reserves signed-response QR capacity before key access. Prepared label statements reuse SQL preparation without caching wallet results or authorization. These changes preserve existing wallet, registry, backup, credential and proposal formats.

The [October assessment](testing/post-5.3-final-status.md) and [execution record](testing/post-5.3-execution.md) describe their exact tested sources, not every later commit. Physical phone/Miniscript acceptance and current-source approval remain separate. The [current maintenance record](testing/maintenance-2026-11-07.md) owns this campaign's checks and remaining work.
