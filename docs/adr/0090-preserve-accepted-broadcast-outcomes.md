# ADR 0090: Preserve accepted broadcasts through local recording failure

Status: accepted for the owner-requested 5.3 defect remediation, 2026-10-18. Refs #116; audit D1. Extends ADR 0013 without changing transaction authorization.

Once Core accepts the exact reviewed transaction, later local persistence errors return an accepted result with its authoritative transaction ID, `persistencePending: true`, `syncPending: true` and a null snapshot. A committed result retains its actual snapshot; a later refresh failure sets only `syncPending`. The renderer must not normalize an absent snapshot, show an ordinary send failure, or invite another payment from that pending-recording result. Show a durable warning and the accepted txid; instruct the user to sync and not resend.

The existing saved PSBTv0 proposal contains the unsigned transaction. Groot's supported native-SegWit software, hardware and multisig transactions have the same txid before and after witness signing. Native sync reconciles an active proposal only when its exact unsigned txid occurs in the canonical wallet graph. It atomically updates the existing proposal status/txid, intent labels, replacement lineage and broadcast notification with the synchronized wallet state. Cancellation and unrelated proposals remain untouched. No renderer-supplied transaction identity is used for repair. Core observation remains authoritative under the existing network trust model.

This does not promise cross-system atomicity: Core acceptance and local commit cannot be one transaction. A crash before the response still requires sync; unavailable Core/storage leaves the existing proposal recoverable and must not be described as proof of rejection. Post-acceptance worker/process termination is not hidden by this result type. Repair runs during ordinary Core/compact-filter sync and completed recovery reconciliation.

Compatibility: no database, registry, profile, credential, PSBT, backup or label format changes; no migration/discard or new receipt store. Existing applications can read the existing rows. The IPC result allows a null snapshot and adds a recording flag; the bundled renderer and native adapter change together. No dependencies or release trust material change. BIP125/174 semantics are unchanged; tests extend application outcome/recovery evidence, not standards support. Broader legacy-script support must revisit unsigned/signed txid equality before reusing this repair rule.
