# Bitcoin standards

**Upstream status** and Groot support are separate: each linked BIP owns its current upstream status. This matrix describes the current source, not universal platform or release certification. Native tests, real-Core evidence and exact-device acceptance are distinct.

The 0.5.4-rc01 Windows/Linux work, version correction and ADR 0109 exact-commit package approval have no BIP impact. They package the existing BIP84/BIP48/BIP174 and fixed Miniscript implementation on additional internal Testnet4 hosts; they change no descriptor, derivation, PSBT, transaction or persisted-wallet semantics. Platform compilation and driver probes are not interoperability certification.

## Dependency-level protocols

The peer stack conditionally handles BIPs 130, 133, 155, 339 and 324. Groot does not expose these as independent features or promise universally encrypted P2P. Fee presets come from Core, not peer feefilter messages; manual/Tor restrictions remain stricter than dependency defaults.

## Maintenance rule

Update this inventory whenever standards behavior or interoperability evidence changes. Check upstream status at that time; dependency support alone does not establish Groot support.

Post-release maintenance strengthens existing BIP174 phone review: complete previous transactions bind every outpoint to its witness amount/script, and policy-map and signed-response bounds run before key access. Witness-only phone imports require a complete re-export. See [the execution evidence](testing/post-5.3-execution.md); physical camera and signer acceptance remain separate.

Fixed Partner/Family BIP68/112 paths remain test-network previews. Their PSBT sequences bind the selected path; current age, reorgs and role requirements are checked again before finalization. Existing BIP48 origins, descriptors, backups and proposal formats remain unchanged. No direct USB Miniscript workflow or phone enrollment into these policies is certified.

The per-coin path view clarifies existing BIP68/112 behavior without changing it. Relative age starts at each output's confirmation, and the exact earliest eligible inclusion height comes from the verified policy and current native chain state. Later paths do not expire earlier paths. Approximate dates are never script or authorization inputs, and Regtest omits them. The additive snapshot DTO changes no sequence encoding, descriptor, derivation, PSBT field, dependency, database schema or persisted wallet format.

The current presentation/ownership cleanup has no BIP, derivation, PSBT encoding, dependency or persisted-format impact. The macOS camera-signing correction and shared capture lifecycle also preserve payment/UR parsing, native review and transport bounds; they add no certified interoperability. The version correction and internal Windows/Linux packaging likewise add no certified standards support. Record new exact-candidate evidence in [the current campaign](testing/maintenance-2026-11-07.md), [hardware certification](hardware-certification.md) and the applicable dated test record; historical RC details remain in those records and the ADRs.

Phone pairing resume uses the existing encrypted staging file and BIP129 records. Background lock and restart change how the pending key is reached. Refusing to replace a staged key and checking the displayed session before accepting its final QR change no BIP support, derivation, QR encoding, stored format or signer compatibility.

The mobile wallet presentation changes no BIP support, spend eligibility, descriptor values, backup proof or persistence. The Send shortcut reads the current committed snapshot. Transaction review and signing still use the native authority.

The optional marketplace design preview and local public-listing research (ADRs 0111–0113) have **no BIP impact**: arithmetic/state, public-offer normalization and bounded development HTTP transport add no derivation, descriptor, transaction, PSBT or wallet-data behavior. No escrow interoperability, key protocol or Mainnet trading support is claimed.

ADR 0114's separate persistent sandbox API and opt-in SvelteKit screen have **no BIP impact**. They handle synthetic integer-cent/satoshi quotes and independent marketplace account/trade records, never derivation, keys, addresses, descriptors, PSBTs, Bitcoin network traffic or wallet persisted formats. The marketplace workspace snapshot, staged quote/receipt UX, incident-stop and proxy-log privacy refinements have **no BIP impact**. ADR 0116’s guided sandbox has **no BIP impact**: it groups explicitly requested synthetic events and changes presentation without touching derivation, signing, transaction formats, onchain protocol support or persisted wallet formats.
